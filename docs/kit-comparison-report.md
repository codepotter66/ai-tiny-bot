## 4. 扩展性评估

### 4.1 行走扩展

**套装提供了 8 个 SG90 舵机，远超预期。**

四足机器人需要 8 个舵机（每足 2 轴）或双足机器人 4 个（每足 2 轴），套装数量刚好够。扩展路径：

| 方案 | 所需舵机 | 套装情况 | 代价 |
|------|:-------:|:--------:|------|
| 四足步行机器人 | 8 个 | 刚好 8 个 ✅ | ¥0 |
| 双足 + 头部点头 | 5 个 | 够用，剩 3 个 | ¥0 |
| 履带底盘 | 2 个电机替代舵机 | 需要另购减速电机 | ¥30-50 |
| 轮式底盘 | 2 个 N20 电机 | 需要另购底盘套装 | ¥35-50 |

**结论：套装 8 个舵机基本覆盖了所有基于舵机的行走方案。**

### 4.2 显示屏扩展

| 方案 | 套装 TFT 情况 | 扩展代价 |
|------|-------------|---------|
| 保留套装 TFT | 直接用 | ¥0 |
| 升级到 1.3" ST7789 | 补购 ¥10-15 | ¥10-15 |
| 加 SSD1306 OLED 作为第二屏 | 补购 ¥8-12 | ¥8-12 |

套装 TFT 的潜在问题：**需要确认分辨率和驱动芯片型号**。ST7735 系列通常有 128×160 或 80×160 等多种分辨率，128×160 对画精细表情略显不足。如果套装是 0.96" 或 1" 小屏，建议补一块 ST7789 1.3" 240×240 作为主表情屏，套装 TFT 可以作为状态副屏（如显示电量、时间等）。

### 4.3 摄像头扩展

**套装 ESP32 不支持摄像头（无 DVP 接口）。**

| 方案 | 可行性 | 扩展代价 |
|------|:------:|---------|
| ESP32-CAM 模块（OV2640） | ✅ 可行 | ¥25-40 + 需单独烧录器或通过套装 ESP32 做桥 |
| 换 ESP32-S3 + 摄像头 | ✅ 可行 | 需换主控，成本高 |
| 通过 WiFi 连接外置摄像头 | ✅ 可行 | 树莓派 Zero / ESP32-CAM 做代理 |

**建议 v0.1 阶段不加摄像头**。云端 LLM 多模态需要稳定传图，ESP32 带宽和算力都吃力。先把语音对话做稳定，v1.0 再加视觉能力。

### 4.4 语音扩展

**套装完全没有音频输入输出能力。** 这是唯一的缺口。

补购的 INMP441 + MAX98357 解决了核心需求。如果想增强，还可以：

| 增强项 | 方案 | 追加代价 |
|--------|------|:--------:|
| 更好的麦克风 | ICS-43434 I2S MEMS | ¥6-10 |
| 更大声音 | 5W 功放（PAM8610）替换 MAX98357 | ¥3-5 |
| 本地唤醒词 | 在 ESP32 上跑轻量唤醒词模型 | ¥0（软件方案）|

### 4.5 其他传感器扩展

套装传感器区的大部分组件（DHT11、火焰传感器、继电器等）对陪伴机器人无直接用途。但 GPIO 资源足够：

| 外设 | 占用 GPIO |
|------|:--------:|
| I2S 麦克风 | 3 |
| I2S 功放 | 3 |
| SPI 屏幕（套装 TFT 或升级 ST7789）| 4 |
| I2C（传感器共用）| 2 |
| 舵机 PWM × 8 | 8 |
| **已用合计** | **20-24** |

ESP32 30Pin 有约 18-20 个可用 GPIO。8 个舵机占满后 GPIO 紧张。建议：

- 8 个舵机分时复用（不是所有舵机同时动）
- 或通过 I2C 舵机扩展板（如 PCA9685）减少 GPIO 占用
- 套装中的按键、LED、震动开关可通过 I2C 扩展

### 4.6 供电扩展

套装有 103450 锂电池和 USB 5V 升压。需确认：

| 问题 | 影响 |
|------|------|
| 升压板是否有 5V 输出给 ESP32 和外设？ | ESP32 需要 5V 或 3.3V，舵机需要 5V-6V |
| 是否有电量和充电保护？ | 没有的话锂电池安全性存疑 |
| 8 个舵机同时工作需要 1-2A 电流，电池能否支撑？ | 500mAh 锂电池 + 8 舵机可能只够 10-15 分钟连续行走 |

**建议补购**：电流容量更大的电池（1000mAh 703048 尺寸）或分开供电（主板用小电池，舵机用单独的电池仓）。

### 4.6 电池续航分析

103450 锂电池的容量需要确认具体 mAh（一般 103450 规格约 500-800mAh）。按 600mAh 中间值估算：

**静态对话场景（不走动）**

| 功耗源 | 工作电流 | 说明 |
|--------|:-------:|------|
| ESP32 WiFi 活跃 | 80-120mA | WebSocket 连接、语音处理 |
| I2S 麦克风 | 2-3mA | INMP441 工作电流 |
| MAX98357 功放（播语音）| 100-200mA | TTS 播放时峰值 |
| ST7789 TFT 屏幕 | 20-50mA | 取决于背光亮度 |
| **峰值总功耗** | **200-350mA** | 对话中播 TTS 时 |
| **空闲总功耗** | **100-150mA** | 等待唤醒/眨眼动画 |

```
续航估算：
  600mAh / 300mA 峰值 ≈ 1.5-2 小时连续对话
  600mAh / 120mA 空闲 ≈ 4-5 小时待机
  实际体验：充满电约够一整天的间歇性对话
```

**行走场景（舵机负载）**

| 功耗源 | 工作电流 | 说明 |
|--------|:-------:|------|
| ESP32 + 屏幕 + 音频 | 150mA | 基础负载 |
| SG90 舵机 × 8（行走中）| 100-300mA | 取决于负重和步态 |
| MAX98357 功放 | 50-150mA | 边走边说话时 |
| **行走峰值总功耗** | **300-600mA** | 全负载移动 + 播 TTS |

```
续航估算：
  600mAh / 450mA 行走均值 ≈ 1-1.5 小时连续行走
  考虑静止时间，实际约 30-60 分钟有效行走时间
```

**续航增强方案**

| 方案 | 电池规格 | 追加成本 | 续航提升 |
|------|---------|:--------:|:--------:|
| 升级到 1000mAh | 703048 1000mAh（扁平，适合拳头机）| ¥12-18 | 约 1.7× |
| 升级到 1500mAh | 803048 1500mAh | ¥15-22 | 约 2.5× |
| 双电池分离供电 | 主板用小电池 + 舵机专用电池 | ¥15-25 | 最佳但最复杂 |
| 低功耗优化 | 空闲时深度睡眠 + 仅麦克风唤醒 | 软件免费 | 待机可达 8-12h |

**建议**：先按套装自带电池实测续航，如果行走时电量掉太快，再补购更大容量电池。103450 规格（50×34×10mm 扁平）已经比较适合拳头大小，再大就放不下了。

### 4.7 GPIO 与接口资源

ESP32-WROOM-32 30Pin 约 18 个可用 GPIO。接线规划：

| 功能 | 接口类型 | 占用 GPIO | 备注 |
|------|---------|:---------:|------|
| I2S 麦克风 | I2S 总线 | 3 | SD / WS / SCK |
| I2S 功放 | I2S 总线 | 3 | 与麦克风共用 SCK/WS |
| TFT 屏幕 | SPI 总线 | 4 | SCLK/MOSI/DC/RST |
| I2C 总线（传感器）| I2C | 2 | SDA/SCL |
| 舵机 × 8 | PWM | 8 | 需舵机驱动板否则不够 |
| 按键 / LED / 震动 | GPIO | 3 | 复用 I2C 可减少 |
| **合计（基础）** | | **20** | 刚好够用，无裕量 |

**8 个舵机直接 PWM 的问题**：ESP32 只有 16 个 PWM channel，8 个舵机占满后几乎没有裕量给其他 PWM 设备。

**解决路径**：

- 舵机扩展板（PCA9685，I2C 控制 16 路 PWM，¥8-15）——推荐
- 或者舵机分时复用（不是所有舵机同时动，步态算法可优化）
- 套装已有 I2C 总线，直接挂 PCA9685 不额外占 GPIO

## 6. 扩展与主控更换判断

### 6.1 需要更换主控的场景

以下场景 ESP32-WROOM-32 无法胜任，**必须更换主控**：

| 场景 | 为什么 ESP32 不行 | 推荐替代方案 | 成本 |
|------|------------------|-------------|------|
| **本地运行小模型** | ESP32 SRAM ≤ 520KB，算力弱，跑不了任何 LLM | ESP32-S3（1-2MB PSRAM）或树莓派 Zero 2W | ¥40-70 |
| **多模态对话（语音+视觉）**| 需要同时处理摄像头流 + 音频流 + WiFi，ESP32 带宽和算力都不足 | 树莓派 Zero 2W（ARM64，1GB RAM）| ¥150-200 |
| **高分辨率摄像头** | ESP32 无原生 DVP 接口，SPI 摄像头帧率太低（<3fps）| ESP32-S3 + OV5640（DVP）或 ESP32-CAM | ¥30-60 |
| **本地语音唤醒词训练** | ESP32 本地跑唤醒词（如"小智"）需要 ~50KB 模型，勉强可行但功耗高 | ESP32-S3 或加唤醒 DSP 芯片（剥豆）| ¥30-50 |
| **高速实时视频流** | WiFi 802.11b/g 瓶颈 + ESP32 处理能力 | 需要 5GHz WiFi 或换 RK3588 类高端板 | ¥200+ |
| **运行 ROS 机器人系统** | ESP32 不是 Linux 系统，跑不了 ROS | 树莓派 4B / Jetson Nano / RK3588 | ¥300-600 |
| **本地存储日志/对话历史** | ESP32 Flash 一般只有 4MB，文件系统受限 | 换带 SD 卡槽的板子或用云端存储 | ¥5-20（SD模块）|

### 6.2 换主控的代价

| 替代方案 | 优点 | 缺点 |
|---------|------|------|
| **ESP32-S3** | 引脚兼容，软件改动小，能跑本地小模型和更多 GPIO | 价格贵 50%，国内购买渠道少 |
| **ESP32-CAM** | 带摄像头一体化，¥25-40 很便宜 | 没有 USB 口，烧录麻烦，GPIO 更少 |
| **树莓派 Zero 2W** | ARM64 Linux，能跑完整 ROS、LLM、多模态 | 体积比 ESP32 大很多（65×30mm），功耗 0.5-1A，价格贵 |
| **香橙派 Zero 3** | 性价比比树莓派高，支持 Linux | 体积中等，功耗类似树莓派 |
| **RK3588 类高端板** | 算力强，能跑 7B 模型 + 多路视频 | 体积大、功耗大、价格高，不适合拳头机器人 |

## 7. 最终建议

### 7.1 购买决策

**买这个套装。**

¥116 含 3D 打印外壳 + ESP32 + TFT 彩屏 + **8 个舵机** + 锂电池 + 面包板+线材，对陪伴机器人来说性价比很高。补购 ¥9-14 的音频模块就能跑起核心功能。

### 7.2 购买后行动清单

**必须补购**：
1. INMP441 I2S 麦克风模块（¥5-8）
2. MAX98357 I2S 功放模块（¥4-6）

**建议补购**：
3. ST7789 1.3" 240×240 TFT 屏（¥10-15）——如果套装 TFT 分辨率不够
4. 更大容量锂电池（¥10-15）——如果要做行走

**确认事项**：
5. 套装附带的 USB 充电管理是什么型号？是否有 TP4056 同等的过充/过放保护？
6. 套装 TFT 屏幕的具体型号和分辨率是多少？
